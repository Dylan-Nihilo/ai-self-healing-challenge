# 修改边界

允许修改 `solution/**`、`tests/solution/**`、`docs/DELIVERY.md`、`docs/AI_COLLABORATION.md` 和 `.env.models.example`。新增 Python 依赖放在 `solution/requirements.txt`。

其他代码、资料、Docker 配置、监测器、自检器、前端、工具 SDK 与验收清单均为固定底座。AI 的调查策略与模型接入由你完成；运行时通过受限工具修改工作站自己的资源，不直接改写核心代码或自检结论。

## 数据与权限

原始资料和原有归档任务必须保留。没有“重置为健康”或任意 shell 工具。工具只允许操作当前工作站的目录、索引、归档配置和任务；不允许任意路径写入或删除资料。

每轮修复使用短期凭据与固定预算，结束后撤销。runner 不挂载业务数据卷，也不持有工作台控制凭据。不要把工具凭据交给模型或写入日志。

## 正式评审

评审方持有冻结基线与清单，通过 `assessment/prepare_submission.py` 只导入允许修改的文件。候选人修改过的框架、测试或检查程序不能代替教师基线；真实 `.env` 和 `.env.models` 不会被复制。

准备程序会生成新的控制凭据，以及默认关闭交互前端、不发布宿主端口的 `compose.eval.yaml`。模型配置由评审方另行提供。

如果发现底座缺陷，应提交复现说明，由招聘方统一修复。不要通过改固定规则绕开缺陷，也不应把未公开要求作为扣分项。
