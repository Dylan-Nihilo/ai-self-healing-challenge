# 自检检查的是真实功能

`core/workstation.py` 同时为业务 API 和自检器提供实际能力。这里没有独立的故障模拟服务，也没有供 AI 直接设置的 healthy 字段。

1. **资料读取**：解析实际 `catalog.json`，读取每份原件，核对目录完整性与内容。
2. **全文检索**：查询实际 SQLite 索引，核对一个已知查询是否返回对应资料。
3. **资料归档**：向实际工作队列提交临时检查任务，由归档进程生成 ZIP，再解包、逐份比对。检查任务完成后清理自身临时产物，不改用户任务。
4. **原有任务**：核对保留的任务是否完成，以及归档文件是否存在、校验一致。

检查器约每 5 秒运行，也可手动触发。它和 AI 执行线程独立，修复期间仍可观察真实功能的逐项恢复。每次 API 返回的 ready 都来自检查结果，模型的完成声明不能替代核验。

初始故障和再次演练会修改目录文件、检索表结构或归档运行配置，导致业务操作失败；原件和已经完成的归档不会被删除。当前支持的演练故障范围就是上述资源与任务，不代表任意代码、网络或硬件故障都能恢复。

自检证明当前这些行为符合约定，不是对所有可能输入的完备性证明；模型能力仍需真实演示与代码评审。
