# 部署

## 实现概览  
修复代理实现于 `solution/agent.py` 文件中。  
当检测到故障时，代理首先调用提供的内置工具：  
- `read_log`  
- `read_recovery_manual`  
- `read_snapshot`  

收集到的证据与 `RepairContext` 一起发送给大语言模型。  
模型分析根本原因，并生成描述问题及修复方案的摘要。  
若修复成功，代理返回 `RepairResult`，其中 `outcome="changed"` 并附带摘要文本。  
如果在调用工具或模型推理过程中发生任何错误，代理将返回 `outcome="blocked"`，以遵循时间限制和调用次数规则。

## 演示流程
1. 初始状态：工作站未通过四项自检项目。
2. 代理会自动触发，通过工具获取证据，并向大语言模型请求分析。
3. 代理返回 `changed`，系统应用修复操作，所有自检均通过。
4. 手动触发新故障后，代理会执行相同的流程并再次恢复系统。
5. 本地暂无法进行屏幕录制。初始恢复和第二次恢复流程可在官方评估环境中重现。

## 依赖项
- `openai` 已在 `solution/requirements.txt` 中声明。
- 模型凭据存储在 `.env.models` 中，不会被提交。
